## Review and device acceptance

The independent V6 review passed the exact integration after reviewing original and revision persistence, capture retry, unknown-outcome consent, Markdown lifetime and the provenance of each local gate. The [local gate receipt](gate.json) includes 61 gate tests, 167 Recorder tests, 38 iOS support tests, typechecking, 16 Chromium outcome scenarios and all three platform startup checks. The [Android receipt](android/outcomes.json) covers an actual save and share, with byte-identical recipient files, then a cold summary reopen in airplane mode. The [iOS receipt](ios/outcomes.json) covers a cold launch without saved Staging credentials and a real Files destination. Independent iOS network isolation remains unverified.

[Compare the three runtimes](outcomes.png). Full resolution captures are in [Android](android), [iOS](ios) and [Web](web). The [generated four-second speech fixture](cedar-markers.m4a) has SHA-256 `8a295edf4add565869f510cb0de211bec2005d531ff7a4fb86cca7f8c36a9d16`.

For iPhone acceptance, select AI Recorder 0.1.9 (17) in TestFlight. Save the speech fixture to Files, import it in Library, play and seek, then share the original audio back to Files. In Settings select Staging. Check the upload disclosure before transcribing the fixture. Save an edit, open Original, share the transcript to Files and confirm the Markdown contains the saved edit. Relaunch in airplane mode and reopen the audio, original and edit. A previously saved summary can be checked offline without buying a provider request. See the [Apple handoff receipt](testflight.json) for upload, processing and group status.
