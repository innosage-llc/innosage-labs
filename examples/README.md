## What we will add

A new example is useful when someone outside InnoSage can reproduce the outcome without knowing our private infrastructure. Each addition should include:

- The real problem and when to use the artifact.
- Prerequisites and a short start path.
- Verification that was **actually performed**, or an explicit "not tested" note.
- Limitations, security boundaries, and the original canonical source.

If the artifact belongs to an existing upstream repository, link to it instead of copying and maintaining a second version.
