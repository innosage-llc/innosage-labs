# Recorder VoiceProfile v1

Status: contract for #127, not yet a service or product availability claim.
[Wire fixtures](v1.fixtures.json) contain made-up data only.

## Authority and privacy

The existing InnoSage Pro Worker verifies the key/entitlement on the selected
Staging or Production origin. It obtains the account scope from its server
authority and uses it together with the deployment environment. No client
account, environment, Router credential, provider identifier, similarity score
or voice vector is accepted as authority. Change credentials or environments
only for new jobs; a retry always targets the original operation and account.
Reject foreign profile/operation identifiers indistinguishably from missing
ones, including mixed valid/foreign candidate lists. Entitlement endpoints
deny unauthenticated/Free callers without accepting their audio. Router
upload/control capabilities remain separate authorities scoped to a job.

For V1 all endpoints in this document are opt-in. An unsupported deployment
does not silently use a different environment, identify without permission,
or turn an existing job into a new job. Do not write private audio, transcript,
profile names, credentials, provider responses/vectors or private IDs to
logs, public issues, analytics, traces or evidence. Disable body/request
logging and caching on these routes. Audio already transmitted for plain
transcription is not consent for enrollment.

## Profile lifecycle

Version identifier: `recorder-voice-profile/v1`. Profiles belong to
one account in one environment. `profileId` is an opaque Recorder-owned
identifier generated by the service, stable across sample changes/restarts
and never reused after deletion. Display name is required (trimmed, 1–100
Unicode code points); it need not be unique. A profile has a nonnegative
integer `revision` incremented on mutation and status `active` or
`disabled`. Enrollment is active only when the service has committed a sample
and consent binding. GitHub account binding is optional and separate from
enrollment; it must not be inferred from names, voice, or summary text.
The service tracks a separate private enrollment revision for matching. A
display-name edit changes only the public profile revision; disabling or
changing samples invalidates a previously admitted enrollment revision, even
if the profile is enabled again before the job completes.

| Pro Worker operation | Request and outcome |
| --- | --- |
| `GET /api/voice-profiles/v1` | Returns the caller's active and disabled profile summaries. No enrollment media, service tokens or vectors. |
| `POST /api/voice-profiles/v1` | Creates a profile from a display name and one consented single-speaker audio clip. Returns the committed summary only. |
| `POST /api/voice-profiles/v1/{profileId}/samples` | Explicitly adds or replaces a consented clip. The multipart JSON `metadata` contains `mode` (`"add"` or `"replace"`), `expectedRevision`, `sample` and `consent`. Never changes identity and does not re-enable disabled profiles. |
| `PATCH /api/voice-profiles/v1/{profileId}` | JSON body has `expectedRevision` and at least one of `displayName` or `status` (`"active"` or `"disabled"`). Disabling immediately excludes the profile; re-enable only if there is still valid consent and retained enrollment. |
| `DELETE /api/voice-profiles/v1/{profileId}` | Stops all future recognition with the profile and removes its enrollment materials. No early success when deletion is pending. |

Profile mutations carry an `Idempotency-Key` generated and retained by the
Recorder. Bind it to account, environment, operation, target, normalized
metadata and audio bytes. With the same input, recover the result after loss
of the response or restart; with changed input, return a conflict without
further mutation. A recovered mutation must not return destroyed enrollment
data or recreate a deleted profile. Store bounded outcome/tombstone evidence
independently of voice material. Stale expected revision on a *new* key is
a conflict. Successful DELETE (204) means materials are gone from active
storage; on durable but incomplete cleanup return 202 and retry the same
operation until cleanup completes. The pending profile is already excluded.
Backups multiply copies: record revocation/tombstones separately, apply them
before restoration is queryable, and expire or destroy affected backups on a
bounded schedule documented by the operator. Never restore a deleted profile.

Enrollment accepts multipart `metadata` (JSON) and `audio` (M4A/AAC or PCM
WAV); verify format and finite decoded duration server-side. Bound a request
to 10 MiB and decoded clip to 2–30 seconds. Reject poor quality, overlap, or
insufficient single-speaker evidence rather than make an active profile.
`sample.source` is `direct` or `confirmed_segment`. For a confirmed segment
the Recorder sends **only** the clipped source range from the existing local
recording, and includes the opaque Recorder-generated `recordingRef` namespace,
`segmentId`, `startMs` and `endMs` in `sample` as provenance, not access authority. If source no longer exists or
cannot be clipped, use direct enrollment; do not upload the full recording
again or retain Router jobs past their current cleanup. Require a fresh
participant-consent confirmation for the selected clip before transmission,
represented by `consent.scope: "voice_profile_enrollment"` and
`participantConfirmed: true`. This is an app attestation, not independent
proof of a participant's consent. Replacing/adding a clip, even from a
correction, requires a separately affirmative action and consent; renaming a
speaker in a transcript does not enroll. Retain minimal private consent
binding and processing outcome, not unnecessary raw audio. Delete temporary
audio on both success and failure; no access after revocation.

Create returns 201; a successful replay, sample write, or PATCH returns 200,
with `{contract, profile}` using the summary shape in the fixtures. List
returns 200 with `{contract, profiles}`. DELETE uses the status-only semantics
above. Use 400 for malformed
metadata/IDs, 401/403 for auth/entitlement, 404 for foreign or absent IDs, 409
for revision/idempotency conflicts, 413 for size, 422 for invalid samples, and
503 for temporary service failure. Error codes are bounded, free of private
details. Retrying the same invalid input must not create a profile.

## Recognition and recovery

Extend the existing paid `POST /api/transcriptions/reserve` request with
optional `voiceIdentification`. An absent option preserves the existing
plain/anonymous path. Present options must name the contract and request
diarization. Omitted `candidateProfileIds` means the account's active
profiles, snapshotted at first successful reservation. An empty list means
match no profiles. An explicit list has at most 64 distinct opaque IDs;
canonicalize list order for replay. Exclude disabled profiles at resolution.
The Pro service snapshots candidate IDs/private enrollment revisions and binds the normalized
input to the existing idempotency key. Replays do not pick up newly enrolled
people or changed samples; changed options conflict. Before identifying and
before serving a result, check that selected profiles are still active and
their enrollment revisions still valid. A candidate disabled, deleted or
sample-replaced since operation admission cannot produce or re-expose a match
from that snapshot. Do not reassign to a runner-up based on the revocation.
A name-only edit does not invalidate the voice evidence.

An acknowledged reservation adds `voiceIdentification: {contract:
"recorder-voice-profile/v1"}` to the existing response fields, including
`decision`, `diarization`, `speakerResultContract` and the job capabilities.
The reserve key remains `recorder-transcription-v2-<10-digit-expires-at>-…`
and retains the existing recovery/expiry semantics. Do not send the job if required acknowledgement is
missing; an explicit user-selected new anonymous operation can use the old
path. The existing Router status, `/transcript`, `/speakers` and cleanup
semantics are unchanged. For opt-in jobs only, the Router control capability
reads a private `GET /v1/sessions/{sessionId}/voice-identification` resource
after transcription reaches completion. It cannot enroll or read profiles.
No bearer returns 401; a wrong-job control capability and a nonexistent
session with a supplied bearer return the same generic 403 on this resource.
The Router does not authorize this read using a client-supplied account or
Recorder operation ID.
Identity processing is bounded by the server and may finish after ASR.
While it runs, return HTTP 202 with `{contract, status: "pending"}`, no
segments and `Retry-After: 2`. Persist and show the usable original first;
retry the same private resource without another reservation or upload.
At most 90 seconds after ASR completion, this resource returns HTTP 200 with
`completed` or `failed`; on timeout use `recognizer_unavailable`. Do not
invoke cleanup merely because ASR completed while matching is pending.
The user can abandon matching and clean up sooner without losing the plain
original. Do not extend the existing session retention or capabilities to
wait for matching. `completed` includes valid empty/unknown
outcomes, `failed` uses one of `recognizer_unavailable`,
`segmentation_unavailable` or `invalid_result` and no named matches. No
provider-specific payload is forwarded. Downloads are safe to replay until
existing job cleanup; same-key recovery preserves the resolved operation
without uploading or transcribing again. Malformed, missing or failed
identification never invalidates a usable original or anonymous attribution.

## Structured result and correction

Keep the plain original immutable. The normalized result preserves the published source row order and carries
segments with stable `segmentId` (unique within the operation),
`startMs` / `endMs` (integer milliseconds, start <= end),
`text`, and `speakerId` (local to this recording, `null` when anonymous
segments could not establish one). Two recordings can use different speaker
IDs for the same profile, or reuse a local label for unrelated people. The
existing anonymous representation and presentation remain usable. Use
published source segment boundaries and text; do not re-sort out-of-order
source rows or stretch zero-length source points. Nonzero intervals are
half-open. Preserve point rows and any anonymous label, but do not attach a
named match to a point. Bind corrections to stable
segment or recording-local speaker IDs independent of paragraph layout.
Retain segments with attribution even if recognition fails. If segmentation
itself is unavailable, keep plain original; do not fabricate speaker IDs.

Each segment disposition is:
- `matched`: has one `matchedProfileId` and a resolved recording-local speaker.
- `needs_review`: evidence is ambiguous (e.g. close ranking or conflict), no
  `matchedProfileId`. Keep the anonymous label; no automatic association.
- `unknown`: insufficient or no eligible evidence, no `matchedProfileId`.
  Keep anonymous labels. Overlap can stay anonymous; V1 does not name two
  speakers on one segment.

Resolve provider evidence server-side. Qualify model/weights, audio-quality
rule, open-set threshold and runner-up margin in staging; never use nearest
neighbor alone. If evidence conflicts across segments for one recording-local
speaker, surface review instead of silently choosing different names. Missing
provider capability fails closed rather than converting segmentation confidence
to identity confidence. Edge extraction, matching and embedding storage are
private, using explicit model/artifact-version compatibility. Preserve only
normalized outcomes and safe errors at this boundary. Alternate adapters may
advertise normalized enrollment and open-set recognition capabilities, not
expose vendor IDs, vectors, or promise a hosted route.

Record a manual correction as an editable revision/annotation with source
reference, not mutation of the original transcript or proof of speaker
identity. A user can correct a segment or a recording's speaker label without
changing a VoiceProfile. Deletion prevents future matches; previously saved
local transcript revisions remain local user content, not active enrollment.
Names associated with revoked/disabled profiles cannot be served as fresh
recognizer results. Summary generation continues from the selected original or
saved revision with the existing configured summary provider/source semantics.

## Action item to GitHub

A speaker match is not the action-item owner. Save a source recording and
time reference, proposed owner and independently resolved GitHub assignee.
There is no automatic GitHub write based on a name, match or model output.
Confirm issue content, destination repository and exact GitHub account
explicitly before creating, even when a stored account binding exists. Use a
stable private create operation and reconcile uncertain external results
before retrying; if exact correlation cannot be verified, surface unresolved
rather than submit again. Compare the returned assignee with the authorized
account and record discrepancies. Keep private transcript snippets and voice
information out of the external issue; a source reference does not authorize
publishing its content.

## M2 rollout outline

Keep Qwen and anonymous segmentation unchanged. Enable the after-segmentation
recognizer only on an isolated Mac Studio staging candidate behind the existing
service authority, private transport and serialization/admission limits.
Give Staging and Production separate state roots, credentials, backup/restore
targets, flags and deploy identities; do not change or restart the shared
production speech service for the rehearsal. Test pinned artifact/runtime
identity, local synthetic lifecycle, service restart, encrypted backup restore
with revocation semantics, and rollback by disabling matching independently of
transcription. The M2 owning runbook must give auditable commands, exact
version/hash/license evidence, configuration validation, health/smoke tests and
impact measurement. Bilingual accuracy and real-use evidence are not implied
by these fixtures.
