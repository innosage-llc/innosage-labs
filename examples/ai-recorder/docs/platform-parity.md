# Recorder acceptance matrix v2

The [product promise](../README.md#product-promise-and-release-status), [master issue #35](https://github.com/innosage-llc/innosage-labs/issues/35) and [owner decision #139](https://github.com/innosage-llc/innosage-labs/issues/139#issuecomment-7230177960) define the common outcomes. Platform differences belong at the microphone, file, secret-store, share, network and presentation boundaries. Use a local synthetic recording with a known digest, an original transcript and a distinct saved edit. A service call must be explicit. Reopening local material must work offline.

## Exceptions and independent decisions

- Staging guest access requires an exact allowlisted build input. The historical default service selection does not provision a guest. Each environment has its own identity and operations. The 15-minute / 50,000,000-byte Free boundary applies before or at admission.
- Large-audio Pro has a separate four-hour / 512 MiB contract and an existing Android native upload adapter. Track durable upload and recovery per platform in [#142](https://github.com/innosage-llc/innosage-labs/issues/142).
- Production Free remains subject to the existing protected Android rollout and its own exact build input. Cross-platform qualification and any eligibility decision belong to [#143](https://github.com/innosage-llc/innosage-labs/issues/143). Personal OpenAI transcription is explicitly selected, needs the user's project key and accepts a new M4A smaller than 25,000,000 bytes.
- [#127](https://github.com/innosage-llc/innosage-labs/issues/127) covers voice-profile matching. Existing optional service-supplied speaker labels do not establish enrolled-speaker identity. [#138](https://github.com/innosage-llc/innosage-labs/issues/138) covers an iPhone downstream handoff. Cross-device sync, a general recipe marketplace and uninterrupted recording after browser/OS termination have no release promise here.

The tested service rollout exclusions below represent current explicit release decisions. Update the issue, adapter and this table together after approval. An ordinary missing implementation or unrun test belongs in the outcome inventory.

## Checking a change

Run the existing local premerge gate. Its Recorder package tests check common admission, retry/operation identity, transcript completion and file serialization. The parity test rejects platform forks of named shared policies and checks positive and negative release eligibility. Each changed outcome also needs a run through the actual app entry on the affected platforms, with identical synthetic content and separately reported permission, local persistence, network and receiving-app results. Link head/base/integration and evidence. A missing or unreachable entry stays an explicit gap with an owner and issue. A new platform exception requires product review and a reason in this matrix.

The local premerge flow runs `npm run test:browser-parity` from the Recorder package. It builds a fresh production Web export using only the approved Staging target, serves it on loopback and drives headless Chrome with synthetic media and intercepted provider responses. The output records its exact export digest and browser version. Provider-service readback and an actual native receiving destination need independent receipts.

When a change affects iOS Markdown, the same local gate runs the native Save to Files scenario after the iOS startup check. It uses a fresh dedicated Release Simulator and repository synthetic data, with no provider actions. The iOS `result.json` binds the outcome to the exact candidate and built app and records the Files export, original audio and transcript hashes. Run the iOS-only replay with the existing `scripts/recorder-gate/platform.mjs` command and its exact integration candidate manifest. This exercises Files on the Simulator. It does not establish device or live-service acceptance.


### Library Import (#146)

The shared action and admission contract lives in `libraryImport.ts`. A single activation in idle state opens one picker. Cancellation is quiet. The selected source must have an M4A name, readable nonempty bytes, a supported audio-only MP4 declaration and decoded audio samples. Only the final committed original and its label appear in Library. Transcription limits and consent apply to later explicit actions.

The adapters in `mediaLibrary.ts` and `mediaLibrary.web.ts` supply picker, bounded file/decoder evidence and storage. Android and iOS use isolated native decoders on picker copies. Web uses a detached muted media element. The iOS toolbar, Android app bar and Web header render the shared action using their platform controls. Build 18's leading iOS duration placement is a presentation decision in #139. The existing Production Free and large-audio restrictions retain their recorded scope.

When changing a PRD outcome, update its row above and register its shared policy, mounted entry, native adapters and matching runtime observers in the local gate. A new OS exception needs the issue, evidence and product approval in this matrix. The first registered slice is Library Import. Each required platform reuses its existing release artifact for the focused observer. Review checks the changed source against the registration, including whether a product decision was introduced inside an adapter.
